# Учёт аренды — контекст проекта

Мобильное приложение для арендодателей: квартиры, договоры, оплаты, счётчики, брони, расходы и доходность. Публикация планируется в RuStore (Android). Сейчас этап кликабельного HTML-прототипа: дорабатываем интерфейс и логику, потом переносим на Flutter.

Общение с владельцем проекта — на «ты», по-русски. Давать только проверенную информацию: если факт не проверен, так и говорить.

## Файлы

- `index.html` — рабочий прототип, один файл: HTML + CSS + JS без сборки и библиотек. Открывается двойным кликом в браузере. Данные хранятся в `localStorage` под ключом `arenda-proto-v1`.
- ТЗ (полная версия, живой документ): https://claude.ai/artifact/ADJjKS2HRQoRdKnomd9zyS
- Опубликованный прототип: https://claude.ai/artifact/TUcZPtA8VHS9wHAG2TLVbY

## Принятые решения

1. **Роли.** При первом входе пользователь выбирает роль: «Частник» (свои квартиры) или «Агент» (квартиры собственников). Роль определяет набор функций, тариф зависит от числа объектов внутри роли. Частник с 6+ квартирами не становится агентом, а переходит на старший тариф.
2. **Тарифы (черновик).** Частник: 1 объект бесплатно, подписка до 5. Агент: линейка по числу объектов (например до 10 / до 30 / без лимита). Цены не определены. Ориентир конкурента RentDesk: 199 ₽/мес за 3 объекта, 499 ₽/мес за 10.
3. **Тип аренды задаётся у каждого объекта**, а не глобальным переключателем: `long` (долгосрочная) или `short` (посуточная). База общая, меняется набор вкладок в карточке.
4. **Закладка арендатора** только для долгосрочной аренды: следующая оплата, «Я оплатил», передача показаний с фото, заявка о поломке. Гостю посуточной аренды позже — ссылка с инструкцией по заселению.
5. **Счётчики электричества:** тип задаётся в карточке объекта — однотарифный, двухтарифный (Т1 день, Т2 ночь), трёхтарифный (Т1 пик, Т2 ночь, Т3 полупик). В форме показаний ровно столько полей, сколько зон, плюс автоматическая сумма. Тип можно сменить в «Тарифах».
6. **Фото счётчиков:** арендатор обязан приложить фото. Его показания получают статус «Проверить», арендодатель сверяет с фото, подтверждает или исправляет (запись помечается «исправлено»).
7. **ТГ-канал с объявлениями отложен.**

## Дизайн-система прототипа

Шрифты (Google Fonts): **Unbounded** 500/600 — заголовки и крупные цифры, скупо; **Golos Text** 400/500/600 — весь остальной текст. Цифры — `tabular-nums`.

Цвета — палитра «Шалфей» (по образцу трекера сна): токены на `:root`, светлая и тёмная тема (`prefers-color-scheme` + `data-theme`, переключатель в Профиле, хранится в `localStorage` под `arenda-theme`).

- **Светлая:** зеленовато-серый фон со свечением в углах; карточки матовые — полупрозрачный белый градиент (`--card`), светлая кромка (`--edge`), мягкая тень (`--shadow`), размытие фона.
- **Тёмная:** графит почти до чёрного, едва заметное зелёное свечение, карточки — тонкий светлый градиент поверх графита.
- **Главный блок экрана** (`.hero`: «Получено» на Главной, «Чистый доход» в Финансах, оплата у арендатора) — глубокий лесной зелёный с плавным графиком (`spark()`), одинаковый в обеих темах. Нижнее меню, основные кнопки и выбранный фильтр — тот же зелёный.
- **Вкладки и переключатели** — дорожка-капсула, выбранный пункт — белая (в тёмной теме графитовая) пилюля.
- **Зерно** — шум поверх всего экрана (`body::after`, SVG feTurbulence, `--grain` .08 / .1).
- Крупные цифры — Unbounded 300 (тонкие, как в образце).

| `--bg` | #ECEEE8 | #0F1110 | фон |

| `--ok/--warn/--bad/--info` + `-soft` | | | статусы (оплачено, внимание, долг, ожидается) |

Иконки: собственный набор SVG-глифов `G` (двухцветные: контур + заливка 22%), значок `ico(имя, тон, размер)` на мягкой подложке и мини-иконка `mi()` для подписей. Счётчики: капля со снежинкой (ХВС), капля с огнём (ГВС), молния (свет), солнце / луна / закат (Т1 / Т2 / Т3). Категории расходов, события, тип объекта — тоже со своими иконками. Показания на вкладке «Счётчики» — плитки с «барабаном» цифр, как в окошке настоящего счётчика (`odo()`), дробная часть красная.

Компоненты: верхняя липкая шапка с меткой «прототип»; нижнее меню из 4 вкладок (Главная, Объекты, Финансы, Профиль) — плавающая тёмно-зелёная капсула; карточки `.card` и списки `.list/.row`; статусы — пилюли `.pill` (`p-ok`, `p-warn`, `p-bad`, `p-info`, `p-mute`); подписи без капса, обычный регистр; формы — нижние шторки `.sheet`; плашка даты `.date` (число + месяц); вкладки `.tabs`. Ширина колонки до 480 px, боковые отступы 16 px.

**Движение** (ориентир — приложение Luma). Три кривые-токена: `--spring` (пружина с перелётом: пилюли, нажатия), `--glide` (мягкое торможение: экраны, блоки), `--sheet` (шторки, как в iOS). Функция `motion()` после каждой отрисовки:
- подсветка-пилюля (`slide()`) переезжает к выбранному пункту в нижнем меню, вкладках карточки, фильтрах и переключателе темы;
- при смене экрана блоки появляются по очереди (класс `.a`, задержка `--i`): разделы меню — снизу вверх, вглубь (карточка, экран арендатора) — справа, назад — слева, вкладки карточки — со стороны выбранной вкладки;
- суммы «набегают» от нуля, полоса прогресса растёт, барабаны счётчиков прокручиваются;
- шторки выезжают снизу, при закрытии уезжает их копия; ошибка в форме — лёгкое покачивание; уведомление — капсула на пружине;
- обновление данных без смены экрана (отметка оплаты и т.п.) ничего не анимирует; при `prefers-reduced-motion` движения нет.

## Правила логики

- **График платежей** строится помесячно от начала договора до текущего месяца (не дальше конца договора). Дата платежа = `payDay`, обрезается до последнего дня месяца.
- **Статус месяца:** `paid` (внесено ≥ плата) → `claimed` (арендатор нажал «Я оплатил», ждёт подтверждения) → `partial` (внесено частично, срок не прошёл) → `late` (срок прошёл, внесено меньше) → `due` (ожидается).
- **Долг** = сумма недоплат по месяцам, срок которых уже прошёл.
- **События на главной:** просрочки, оплаты на проверке, ближайшая оплата, конец договора за 45 дней, показания на проверку, напоминание передать показания (20-е число), заезды и выезды на 14 дней вперёд. Сортировка по дате.
- **Брони:** пересечение дат запрещено (`from < x.to && to > x.from`); сумма по умолчанию = ночи × цена за сутки.
- **Показания:** новые не меньше предыдущих по каждому полю; исправленные — не меньше предыдущих и не больше следующих. Расчёт коммуналки — по двум последним показаниям × тарифы, по каждой зоне отдельно.
- **Финансы:** доход долгосрочной = полученные оплаты за год; посуточной = оплаченные брони по дате заезда; у агента комиссия = доход × %.
- **Фото** сжимаются в браузере до ~900 px, JPEG 0.6.

## Интеграции с Авито и Циан (что известно)

- **Авито, посуточная:** календарь объявления можно синхронизировать по ссылке-календарю (iCal): так работает, например, M-Bron. Изменения применяются примерно в течение часа, поэтому возможны двойные брони. Требует сервера, отдающего ссылку `.ics` по каждому объекту.
- **Авито API:** ключи `client_id` и `client_secret` берутся в Авито PRO → «Профиль и настройки» → «Интеграции и API». Есть сообщения, объявления и их статистика, звонки. Наличие API именно для броней посуточной аренды не подтверждено.
- **Циан API:** бесплатный, но только для риелторов, агентств и застройщиков на тарифах «Базовый» и «Застройщик»; ключ выдаётся в профессиональном кабинете. Даёт аналитику, звонки, чаты, жалобы, финансы, сотрудников. Для собственников-частников доступ не подтверждён.
- **Циан XML-фид:** документирован формат долгосрочной аренды квартир (`flatRent`); отдельного формата для посуточной в документации не нашли.
